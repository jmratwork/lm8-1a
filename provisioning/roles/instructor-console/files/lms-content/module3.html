Module 3 — Verifying Attachments and Reporting

Attachment Red Flags

Malicious attachments are a primary delivery vector. Exercise extreme caution with:

  • Executable files: .exe, .bat, .ps1, .vbs, .js
  • Office macro documents: .docm, .xlsm (macros disabled by default for a reason)
  • Archive files: .zip, .rar, .7z (may conceal malicious payloads)
  • PDF files: can contain embedded JavaScript or exploit links
  • Double extensions: invoice.pdf.exe (the real extension is .exe)

Safe Verification Steps

  1. Do not open the attachment on your workstation
  2. Check the file extension carefully (enable "show file extensions" in Windows)
  3. Verify with the sender via a separate channel (phone, Teams) — not by replying to the email
  4. Submit the file to IT Security for sandbox analysis if in doubt

Reporting Protocols

Reporting a suspicious email quickly is as important as detecting it. Your options:

  1. GoPhish Report Button: If the email was sent via GoPhish, use the "Report Phishing" button in the email client or landing page — this records your detection in the training platform.
  2. REP Incident Form: Submit a detection report via the REP Practical Labs incident form, documenting all identified indicators.
  3. IT Security Helpdesk: Forward the suspicious email as an attachment to security@company.internal (in a real scenario).
Key principle: When in doubt, do NOT click. Report first, investigate later with IT Security support.
